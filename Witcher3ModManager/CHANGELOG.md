# Changelog

## v0.9.7 (2026-10-21)

**资料库维护（设置 → 工具）**
- 新增「收进存储」：只把「在游戏目录里、但存储里没有」的组件复制进存储，先告知模组数 / 文件夹数 / 预计体积；游戏目录只读不动，已有副本不覆盖。
- 新增「清空记录」：只清记录、所有权索引与 bin 账本；游戏目录、存储副本、备份都不动；清空前把三个文件另存为 `.cleared-时间戳` 副本。

**结构识别：旧链退役**
- 删除按文件夹名猜结构的整套扫描器（约 210 行），识别只由分析器负责；新结构必须先落 fixture 再改代码。
- 认不出结构时不再自动猜根，改为显式询问「整体安装为 mod 还是 dlc」；取消即什么也不写。
- bin 文件改为按各自 `bin/` 根复制（原来取第一个根，多根时可能复制错源）；包内两个根写同一路径时直接拒绝导入。

**`mods.settings` 格式修正（与游戏、Script Merger 对齐）**
- 旧版写入的是 `"modName" = 优先级`。游戏只认 `[modName]` / `Enabled=1` / `Priority=N` 段格式，所以优先级从未真正生效；Script Merger Remastered v1.7 读到旧格式会直接空引用崩溃。
- 现在读写都按段格式；旧格式行在下次保存时自动转换，不属于本管理器的条目继续原样保留（段保持字节不变，旧格式行无损转成段）。

**之前的修复一并进入本版**
- 删除 bin-only 记录不再误删整个存储目录；`_w3mm_staging` 空壳会被清理；`mods.settings` 读取失败会留诊断日志。
- 修复：游戏目录里只剩一个空文件夹时，启用不再把它当成「已部署」——之前会报告成功但实际什么都没复制（「房子升级」mod 就是这样没生效的）。
- 冲突列表不再统计文档文件（`README.txt`、`readme`、`.md`、`.pdf` 等）：两个 mod 各带一份说明文件不算冲突，Script Merger 同样忽略这类文件。
- 修复：`content\precompiled.rsblob` 不再按「脚本覆盖」报红。它是编译函数的容器，两个不同的 blob 只有函数重叠才冲突（Walk by Default 与 No Map Borders 就是误报）；现在按蓝色「无法静态判断」处理，并提示用 Script Merger 复核。
- 新增脚本符号级冲突检测：读取 `precompiled.rsblob` 的类/函数表与松散 `.ws` 的注解，同一「类::函数」发生**定义级**重叠时报告红色冲突（标题显示符号名，如 `W3DamageManagerProcessor::ProcessActionReaction`）。多个 `@wrapMethod` 包装同一函数是引擎支持的叠加行为，不算冲突；只有 `precompiled.rsblob` 类函数、`@replaceMethod`、`@addMethod`、整类重定义才参与判定。blob 解析失败或版本不认识时退回「无法判断」；脚本内容完全相同的两份副本不重复报告。
- 修复：替换模组后旧记录仍留在所有权索引里，导致孤儿接管提示「已被 X 占用」（两个骑龙 mod 共用 `modFlyingMountsCore` 的实际案例）；现在替换记录时会同步清理旧索引，启动时也会丢弃没有对应记录的索引条目。
- 新增停用前的脚本依赖警告：若其它已启用模组的松散脚本引用了本模组定义的类（例如骑龙包的 `FMCController`），停用前会列出依赖方，默认按钮为「否」，避免停用后游戏启动时报脚本编译错误。
- 新增「已由 Script Merger 合并」状态：读取 SM 安装目录的 `MergeInventory.xml`，当合并产物已安装、启用且合并文件真实存在时，相关脚本冲突从红色降为绿色、不计入红色冲突数；合并 mod 卡片和详情标注「SM 合并产物」。停用或删除合并产物后，冲突自动恢复为红色。
- 导入时遇到已存在的组件文件夹会询问「共享 / 覆盖 / 取消」：共享会保留两个记录、把新包的同名文件合并进同一个文件夹（旧内容先备份到 `Backups\import`），两个 mod 可以各自启停；覆盖仍是原来的替换行为；不确定时默认选共享。
- 改进 bin 接管：启用时若目标文件已存在、且内容与本包完全相同（手动安装过或重复启用），视为「本包的文件」；停用时真正移除，而不是把 mod 文件还原回去。内容不同或哈希无法读取时仍按原逻辑备份并还原。
- 孤儿接管只登记、不复制；只带 bin 负载的模组文件夹也能被发现；预设按记录 ID 保存（旧预设仍可读）；备份目录按记录 ID 存放；预设文件损坏会保留副本并提示。

**工程**
- 新增「手工回归矩阵」（`docs\regression-matrix.md`）与一条命令出包脚本（`tools\release.ps1`：测试 → fixtures → 打包 → 校验产物）。
- 新增设置隔离守卫测试：测试版与正式版的数据目录必须不同。
- **发布包改为单文件**：解压后只有一个 `Witcher3ModManager.exe`，加上 `Resources` 与两个说明文件；不必再在两百多个运行时 DLL 里找启动器。
- **默认背景**换为一张游戏内截图（`Resources\bg_default.jpg`），首次启动就能看到；设置里仍可换成自己的图。
- 修复：启用/停用失败后拨动开关不再触发反向操作（一次点击只产生一次操作与至多一条日志）。
- 「我已处理」现在会列出仍占磁盘的临时目录（路径 + 体积），**不会自动删除**——回滚未完成时它可能是唯一副本。

## v0.9.6 (2026-10-16)

自 v0.9.4 以来的第一批完整记录（v0.9.3–v0.9.5 未单独记载）。

**部署内核（第 16 项，全部由测试驱动）**
- 启用 / 禁用 / 删除三条路径改由同一个「步骤引擎」执行：目标永不直接删除，先移入 `<游戏>\_w3mm_staging`，失败按逆序回滚，无法回滚的步骤单独报告。
- bin 文件可逆：启用前的内容按内容哈希留档，停用/删除时还原（别人在后面写过就还原成别人的那份）；磁盘内容被人改过或没有记录时保持不动并说明原因。
- 删除 bin-only 包不再误删整个存储目录。
- 未完成的操作用日志留痕，启动时提示，并可「我已处理」归档。
- 失败提示精确到「哪个组件 + 什么原因」，不再只说「失败」。
- 临时目录没清理干净会被报告出来，不再静默。

**部署后漂移检测（第 17 项）**
- 「检查资料库」现在会对比索引与实际磁盘：记录为已部署但已消失、或内容被外部改动，都会列出（只读、不自动修复）。

**孤儿接管（第 18 项）**
- 游戏目录里已有的模组可以「接管」进资料库：**只登记，不复制、不移动、不删除任何文件**；被别人占用的路径会拒绝并点名。
- 预设改按记录 ID 记录（旧预设仍可读）；备份目录改按记录 ID 存放；设置里那句与实际不符的备份说明已改正。
- 只带 bin 负载的模组文件夹现在也能被发现。

**其它修复**
- 语言切换的 handler 不再累积；测试版不再读到正式版的设置；诊断日志不再写死 `Z:\griffin_import.log`。
- 版本号收敛为单一来源（`Core\AppInfo`），并有守卫测试防止再散落。
- 若干「静默吞掉」的地方改为明确报告（存储写入、日志读取、预设文件损坏）。
