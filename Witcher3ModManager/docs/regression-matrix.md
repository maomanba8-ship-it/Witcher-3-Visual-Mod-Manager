# 手工回归矩阵

用途：自动化测试（xUnit + FixtureRunner）覆盖不到的部分——真实文件系统、真实游戏目录、
真实窗口——在这里按「前置 / 操作 / 期望」固定下来。每次发布前跑一遍，结果记在最后。

所有步骤都用**测试版**（Debug 构建，标题带 `[TEST]`，数据目录
`%LOCALAPPDATA%\Witcher3ModManager_Test`）。正式版只在最后一步验证一次。

---

## A. 导入

### A1 普通 mod + dlc 包
- **前置**：游戏路径已设置；包里同时有 `modX` 与 `dlcX`。
- **操作**：拖入压缩包 → 导入。
- **期望**：生成**一条**记录，`GameModFolders = [modX]`、`GameDlcFolders = [dlcX]`；存储里两个文件夹都在；
  组件指纹有两条且文件数正确；计划预览里「将新增」列出这两个组件。

### A2 纯 bin 包
- **前置**：包内只有 `bin\config\...`。
- **操作**：导入。
- **期望**：记录名为**压缩包名**（不是 `_tmp_xxxx`）；`GameBinFiles` 列出相对路径；
  `<数据目录>\bin\<记录 ID>\` 里有对应文件。

### A3 认不出结构的包
- **前置**：一个只有 `readme.txt` 或只有 `content\` 的压缩包。
- **操作**：导入 → 在弹出的「无法识别结构」里**先取消**一次，再导入并选择安装类型。
- **期望**：取消时**什么都没有写入**（无记录、存储无新增、游戏目录不变）；
  选择后按「整体安装」生成记录，顶层 `content\` 的层级没有被吃掉。

### A4 bin 与已装模组重叠
- **前置**：已有一条记录带 `bin\config\x.xml`；新包也带同一路径。
- **操作**：导入新包。
- **期望**：弹「bin 文件重叠」，逐条列出 `bin/<路径> ← 哪些模组`；取消后无写入。

### A5 包内两个 bin 根撞车
- **前置**：包内 `A\bin\config\x.xml` 与 `B\bin\config\x.xml`。
- **操作**：导入。
- **期望**：**拒绝导入**并列出冲突路径，什么都不写。

## B. 启用 / 停用 / 删除

### B1 启用与停用
- **操作**：启用一条含 mod+dlc 的记录 → 再停用。
- **期望**：游戏目录出现 `mods\<名>`、`dlc\<名>`；`mods.settings` 出现对应行（外来行保持原样）；
  停用后两处都变成 `~<名>`，内容不动，`mods.settings` 该行消失。
- **格式**：该行必须是 `[modName]` + `Enabled=1` + `Priority=N` 段格式（游戏与 Script Merger 都只认这个）；
  文件里不应再出现旧的 `"modName" = N` 行。

### B2 失败提示到组件
- **前置**：用 cmd 窗口把当前目录停在待停用的文件夹里（PowerShell 不行）。
- **操作**：停用。
- **期望**：弹「停用失败」，正文点名 `mods\<名>` 与系统原因，并写明「已回滚到操作前的状态」；
  模组文件夹仍在原位、记录仍是启用状态（失败不改状态）；
  **会留下一条未完成日志**（设计如此，启动时会提示，可点「我已处理」归档）；
  关闭 cmd 后重试成功，此时不会产生新的残留。

### B3 删除
- **操作**：删除一条记录。
- **期望**：游戏目录与存储里的组件都被移除；记录消失；`mods.settings` 该行消失；
  没有「临时目录没有清理干净」提示（`_w3mm_staging` 应为空且被清掉）。

## C. bin 可逆

### C1 正常还原
- **操作**：启用一个带 bin 的包 → 停用 → 删除。
- **期望**：启用后 `bin-ledger.json` 有该条（writers 一条、original 有值）；
  停用后无弹窗、账本该条消失；删除后账本为空。

### C2 被外部改过
- **操作**：启用 → 用记事本改一下游戏里的该 bin 文件 → 停用。
- **期望**：弹「停用不完整」，写明「现在的内容不是我们写下去的那份，没有动它」；文件保持被改后的样子。

## D. 孤儿接管

### D1 只登记不复制
- **前置**：游戏目录里有资料库不认识的模组文件夹。
- **操作**：顶部横幅 →「全部接管」勾选若干 → 确认。
- **期望**：提示「已接管 N 个…未复制、未删除任何文件」；游戏目录内容与数量**不变**；
  资料库出现这些记录；再次扫描时它们不再算孤儿。

## E. 资料库维护（设置 → 工具）

### E1 收进存储
- **操作**：点「收进存储」。
- **期望**：确认框写明 **模组数 / 文件夹数 / 预计体积**；确认后存储里出现这些文件夹，
  **游戏目录不变**；再点一次提示「没有需要收进存储的模组」。

### E2 清空记录
- **操作**：点「清空记录」并确认。
- **期望**：列表清空、状态栏归零；数据目录出现 `mods.json.cleared-…`、`library.json.cleared-…`、
  `bin-ledger.json.cleared-…`；**游戏目录与存储副本都还在**。

### E3 检查资料库（漂移）
- **操作**：先看一次（应干净）→ 删除或修改游戏目录里某个已部署文件 → 再看一次。
- **期望**：出现「记录为已部署，但游戏目录里已找不到」或「内容已不是我们写下的那份」；
  报告只读、可复制。

## F. 未完成日志

### F1 启动提示与「我已处理」
- **前置**：制造一次失败操作（B2 的做法），关掉程序。
- **操作**：重新启动 → 点「我已处理」→ 再启动一次。
- **期望**：第一次弹「上次操作未完成」并列出条目；处理后日志被移进 `journal\handled\`，
  之后启动不再提示。**若这些操作还留有临时目录**，会再弹一个「临时目录未清理」，逐个列出路径与
  体积——程序**不会自动删除**（回滚未完成时它可能是唯一副本），确认不需要后手工删。

## G. 界面与发布

### G1 语言切换
- **操作**：设置里切换中/英，逐页浏览（模组、冲突、预设、设置）。
- **期望**：所有可见文案都随语言切换，无中英混排；设置页工具区三行说明完整。

### G2 版本号
- **操作**：看标题栏、设置 → 关于、右键 exe → 属性 → 详细信息。
- **期望**：三处都是同一个版本号；exe 的文件版本形如 `x.y.z.0`。

### G3 正式版隔离
- **操作**：运行打包好的正式版一次（只启动即可）。
- **期望**：读的是 `%LOCALAPPDATA%\Witcher3ModManager`，看不到测试版的记录；
  测试版的数据目录不受影响。

## H. 冲突 / 合并 / 共享 / 依赖（2026-10-28）

### H1 脚本符号冲突（仅定义级）
- **前置**：启用 `modDeathsReworkedWoundsAndBrutality` 与 `modCleanScreenRemaster`。
- **期望**：出现 4 条红色脚本冲突，标题为 `类::函数`（`W3DamageManagerProcessor::ProcessAction` / `ProcessActionReaction` / `ProcessDismemberment` / `ProcessFrostDismemberment`）；
  只有 `@wrapMethod` 的组合（如 `OnSpawned`、`OnClosingMenu`）不出现。

### H2 已由 Script Merger 合并
- **前置**：SM 做过合并，`mod0000_MergedFiles` 已安装并启用，SM 安装目录存在 `MergeInventory.xml`。
- **期望**：对应脚本冲突显示绿色「已由 Script Merger 合并（mod0000_MergedFiles）」，不计入红色数字；合并 mod 卡片显示「SM 合并产物」；
  停用或删除合并 mod 后，这些冲突恢复为红色。

### H3 停用依赖警告
- **前置**：`modFlyingMountsCore` 与 `modFlyingMountsRoyalWyvern`、`modFlyingMountsSilverBasilisk` 均启用。
- **期望**：停用 Core 时弹窗列出两个依赖方与 `FMCController`，默认按钮为「否」；选否保持启用，选是才停用。

### H4 共享导入
- **前置**：已安装一个包含共享文件夹的包（如骑龙 Core）。
- **操作**：导入另一个包含同名文件夹的包。
- **期望**：弹「组件文件夹已存在」；是=共享（两张卡、文件合并、旧内容备份到 `Backups\import`）、否=覆盖、取消=不导入。
  共享后停用任意一方，共享文件夹都不会被删除；重新启用后文件回来。

### H5 旧索引清理与孤儿接管
- **前置**：历史上替换记录留下旧索引（骑龙包的 `c8f5...`）。
- **操作**：启动管理器 → 全部接管。
- **期望**：旧索引在启动时被清理；孤儿文件夹可以成功接管；游戏目录保持不变。

### H6 bin 接管（需要手动模拟）
- **前置**：选一个带 bin 的 mod（如“和任何 NPC 发生关系”），停用它，然后手动把它的存储 bin 文件复制回游戏目录。
- **操作**：在管理器里启用 → 再停用。
- **期望**：第二次停用后该 bin 文件被移除（不是被“还原”回来）；启用期间 `bin-ledger.json` 中该路径 `Original` 为 `null`。
